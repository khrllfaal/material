# Hasil QA & Perbaikan (Okt 2026)

Diuji pada data contoh: 30 proyek, 15 bahan, ±350 Bahan Masuk, ±530 Pemakaian.

## Lulus
- Login benar/salah, kunci akun setelah 5 gagal; tanpa login → 401.
- Owner: semua tulis (proyek, bahan, transaksi, user, RAP, tambah-bahan) → 403; tombol tulis tidak tampil di 11 menu.
- Admin Lapangan: hanya proyek yang ditugaskan; tidak bisa ubah/hapus transaksi lama, master, user, RAP.
- Simpan Bahan Masuk/Pemakaian, desimal `0,322`, tambah bahan baru, antrean offline lalu terkirim otomatis.
- Excel/PDF dari Dashboard, Monitor Stok, Analisis RAP, Riwayat; filter kartu status; pencarian; paging.
- Kecepatan API (30 proyek): 5–35 ms per endpoint; 100 input paralel 0,4 detik; balapan ID sama tidak error 500.

## Ditemukan & diperbaiki
- Jumlah negatif/nol, tanggal ngawur atau di masa depan, dan bahan tak dikenal diterima / membuat error 500 → kini ditolak dengan pesan jelas (422).
- Menghapus Master Bahan/Proyek diam-diam menghapus seluruh transaksinya (cascade) → kini ditolak (409) bila sudah punya transaksi.
  Diperkuat di database: `ON DELETE RESTRICT` (schema baru) + `migrations_2026-10-protect-history.sql` untuk database yang sudah berjalan.
- Admin Lapangan bisa melihat daftar semua proyek → kini hanya proyeknya.
- Header keamanan (nosniff, frame DENY, CSP, Referrer-Policy, HSTS bila HTTPS) di API dan frontend (`frontend/.htaccess` + meta CSP).
- Tabel 180–1000 baris dirender sekaligus → kini 50 baris/halaman, header tabel menempel.
- Ikon pencarian tertutup kolom input; tanggal/Aksi terpotong dua baris; Riwayat mobile berupa tabel sempit → kini daftar kartu per tanggal.
- Font kecil (11–12 px) dinaikkan, angka tabular, fokus keyboard terlihat, input mobile 16 px (tidak zoom di iPhone).

## Belum / saran (dibanding sistem perusahaan besar)
- Belum ada layar Audit Log (data sudah tercatat di tabel `audit_log`).
- Belum ada pembatasan percobaan login per IP / CSRF token (cookie SameSite=Lax sudah menahan sebagian besar).
- Pemakaian belum wajib terikat pekerjaan; belum ada persetujuan (approval) transaksi.
- Uji beban sungguhan perlu di server Apache/PHP-FPM; uji lokal memakai server PHP satu-thread.
- Backup: jadwalkan `backend/api/bin/backup_db.php` lewat cron hosting.
- Tidak ada uji otomatis di repo (saat ini uji manual/skrip).

## Absensi & Rekap Gaji (Okt 2026)
- Diuji dengan lembar asli "Absen Upah rumdis Cimahi 2–8 Okt": 48 pekerja, hasil Grand Total
  Rp37.069.000 dan Total Pembayaran Rp29.947.000 (air galon +378.000, kasbon −7.500.000) persis sama;
  jumlah pekerja per hari (31/31/25/32/31/40/47) juga sama.
- Jam lembur yang diinput = jam yang dibayar (lembar kertas menulis 2 untuk yang dibayar 1,5 jam; di sistem ketik 1,5).
- Hak akses: lapangan hanya proyek sendiri, 3 hari ke belakang, tanpa nominal; akuntan hanya
  endpoint gaji; owner hanya baca. Periode dibayar terkunci; koreksi lewat penyesuaian periode berikutnya.
- Filter periode Monitor Stok / Analisis RAP / Dashboard kini mengikuti tanggal transaksi:
  Stok Awal + Masuk − Pemakaian = Stok Akhir untuk periode terpilih.

## Uji kontrol & keamanan gaji (Okt 2026)
- Peran: Admin Pusat tidak bisa mengajukan/menyetujui/mengembalikan/membayar (403); hanya Akuntan. Owner hanya baca.
- Konkurensi: 6 pembayaran bersamaan → hanya 1 yang tercatat (tidak terbayar dua kali); 4 persetujuan bersamaan → 1 menang.
- Dua HP edit hari yang sama: yang terlambat ditolak 409 tanpa menulis sebagian; kirim ulang identik aman.
- Keamanan: CSRF (text/plain & Origin asing ditolak), injeksi pada 7 endpoint tanpa 5xx, mass assignment
  (verifikasi/tarif dari lapangan diabaikan), IDOR antar proyek, cookie HttpOnly+SameSite 30 hari, sesi tetap
  valid setelah 3 jam diam, waktu login unknown≈known user.

## Putaran: kasbon per tim, pengajuan banyak tim, buku panduan PDF (Okt 2026)
- Kasbon atas nama pekerja, **tim**, atau grup; satu pengajuan lapangan boleh memuat banyak tim/pekerja (satu `batch_id`, disetujui/ditolak sekaligus);
  pelunasan (kasbon negatif) dari tab Kasbon; potong otomatis per tim dari sisa gaji anggota tim, sisa dibawa ke minggu berikut, saldo nol tidak dipotong,
  setujui ulang tidak ganda. Kasbon bertanggal di dalam minggu yang dibayar ikut dipotong minggu itu; bertanggal setelah akhir periode menunggu periode berikutnya.
- Gaji bersih negatif memblokir persetujuan (bendera `net_minus`). Penulisan tim dikanonkan (Tim A = tim a); Ganti nama / gabung tim (`rename_tim`).
- Hapus proyek yang sudah punya absen/gaji/kasbon: 409 + ringkasan; boleh bila nama proyek diketik persis (`?konfirmasi=`).
- Zona waktu WIB berlaku untuk seluruh database (NOW(), cap waktu, batas minggu Jumat–Kamis).
- "Nama grup" di pengajuan upah dihapus (satu pengajuan = semua tim); proyek berhenti di tengah minggu bisa langsung Ajukan.
- Tanpa kartu panduan, banner libur, dan tombol buku panduan di aplikasi (PDF panduan dikirim terpisah, tidak ada di server). Tautan "Tandai libur / hujan" saja.
- Pemakaian bahan melebihi stok (HP) meminta konfirmasi. Folder backups ditutup (.htaccess + ekstensi sql/zip/log diblokir di root).

## Putaran: periode susulan & angka (Okt 2026)
- Minggu yang diajukan sebelum akhir minggu (mis. proyek berhenti hari ke-4) dipotong di hari kerja terakhir; sisa hari minggu itu menjadi periode susulan
  yang tetap bisa diisi lapangan dan dibayar terpisah. Periode lama yang sudah terlanjur diajukan/dibayar lebih awal dipotong otomatis oleh migrasi (v5). Diuji (sp.js, 10 pemeriksaan).
- Kolom angka (tarif, kasbon, tambahan) memberi titik ribuan langsung saat mengetik; kolom qty/jam memakai koma desimal.

## Putaran: tim borongan, pekerja berhenti, pekerja di dua proyek (Okt 2026)
- Tim borongan (kolom `workers.borongan`): satu penerima per tim (cat, aluminium, dst), tanpa tarif harian; nominal lewat Tambahan, bayar bertahap (termin), kasbon atas nama tim
  dipotong otomatis dari borongan. Dibuat oleh Akuntan/Admin (Pekerja & Tarif > Tim borongan) atau Admin Lapangan (Tambah Pekerja > Tim borongan). Peringatan bila ada absen tetapi nominal kosong.
- Pekerja berhenti: `action:set_aktif` (lapangan hanya boleh mengubah status aktif); riwayat tetap; nama yang sama yang nonaktif ditawari "aktifkan kembali".
- Pekerja yang sama di dua proyek (`workers.induk_id`): tiap proyek punya catatan sendiri (tarif dan gaji per proyek), tetapi total hari per orang dicek; lebih dari 1 hari memberi peringatan saat simpan dan tanda "ganda" di rekap.
- Migrasi otomatis v6 menambah kolom pada database lama (diuji dari skema lama).
- Hasil: core 29, borongan/nonaktif/induk 36, ui 20, crawl+HP 14 — semua lolos.

## Putaran: beban, banyak pengguna, balapan (Okt 2026)
- Temuan: (1) pembayaran/persetujuan bersamaan bisa tercatat ganda dan dua HP bisa saling menimpa absen. Penyebab: pencarian periode membaca database sebelum kunci periode diambil
  (diperkenalkan bersama fitur periode susulan). Diperbaiki (hasil pencarian diingat per permintaan dan dilakukan sebelum transaksi). Tes balapan: kode lama 2/8 benar, kode baru 8/8.
  (2) simpan absen bersamaan dari banyak proyek bisa deadlock (13 dari 792 permintaan gagal 500): kunci rentang pada baca-sebelum dihapus dan seluruh penyimpanan diulang otomatis bila deadlock. Setelah itu 0 error.
  (3) Rekap semua proyek 60 hari dipercepat 2,6 dtk menjadi 1,0 dtk (pengecekan "ganda" dihitung di memori).
- Data uji: 82 proyek, 2.400 pekerja, 132 ribu baris absen. Rekap semua proyek 30 hari 0,65 dtk, 60 hari 1,8 dtk (3,6 MB sebelum kompresi), 1 proyek 1 minggu 11 ms, daftar 2.400 pekerja 23 ms.
  60 login serentak median 2,4 dtk (bcrypt, CPU); 60 pengguna memuat dan menyimpan absen bersamaan 0 error, simpan median 0,2 dtk; 60 penyimpanan serentak untuk proyek dan hari yang sama semua 200.
- Catatan: dilakukan di server uji 4 inti, bukan Hostinger. Server php -S satu proses (yang dulu dipakai) tidak menguji balapan; gunakan PHP_CLI_SERVER_WORKERS.
